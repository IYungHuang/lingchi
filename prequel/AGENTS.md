# 共同角色操作規則（AGENTS.md）

本文件規定《凌遲》專案全體參與 Agent（總編輯、跟隨編輯、小說作者）的共同操作鐵律。所有角色必須嚴格遵守以下條款：

1. **唯一事實基準（SSOT）**：正式設定以核定之 `canon/`、`shared/canon/` 與 `decisions/` 為唯一準則；對話或提示詞中自發產生之新點子非經總編輯正式裁決，不視為已批准設定。
2. **任務啟動前檢核**：執行任務前必須先讀取 `prequel/PROJECT.md` 及本輪任務資料包（`tasks/`），發現資料缺失、前置版本衝突或知情矛盾時，應立即停止並回報。
3. **史料誠信與反幻覺原則**：嚴禁將會話摘要、AI生成推論或網民發言當作歷史定論；嚴禁虛構發明網址、頁碼、引文、檔案卷號或朝廷公牘。
4. **四分標識原則**：專案中之所有資訊嚴格區分為：
   - 【已核實史實】：有確鑿版本、頁碼或檔案支持；
   - 【研究推論】：基於史料的合理制度邏輯演繹，需標記推論依據；
   - 【作者虛構】：為情節或戲劇性服務之設計，必須於 `canon/fiction_register.md` 正式登記；
   - 【待查證】：存疑項，嚴禁擅作肯定結論。
5. **阻擋與解耦原則**：未確認之承重史實（如官制、刑名、法令時間）僅阻擋與其直接相依之章節場景，不阻擋其他可獨立開展之研究與設計。
6. **調度與版本控制唯一性**：只有總編輯主進程擁有派發任務單、裁決爭議、執行 Git 操作之權限；子 Agent 嚴禁再次派發子 Agent，亦嚴禁執行任何 Git 指令。
7. **任務完工標準化回報**：每次任務完成必須回報：讀取版本基準、寫入檔案路徑、主要產出成果、未完成事項、待決策點、以及是否有越權變更情況。
8. **權限隔離與邊界保護**：提示詞約束非底層物理權限。主進程應提供最小充分資料包；作者與編輯嚴禁越權跨目錄修改非授權檔案。
9. **並發互斥原則**：禁止多個角色同時修改同一檔案。作者只處理明確指派之章節正文與筆記；編輯只處理審稿報告與研究提案。
10. **正傳文稿保護原則**：正傳《至斬而止》既有文稿（`manuscript/`）與台帳保持嚴格原狀，嚴禁自動搬移、覆寫或刪改；若遇跨作品設定衝突，必須呈報影響分析由出版決策者（用戶）裁決。
